        Set up SuperLink → MQTT → Home Assistant

        superlink2mqtt is an independent bridge. The radio receives SuperLink packets, the bridge manages sensors and publishes MQTT, and Home Assistant discovers entities through its MQTT integration. The Home Assistant app runs that same bridge in a sidecar container.

        1. Connect the radio and broker

        In the Home Assistant app Configuration tab, set the Pi’s radio_host, radio_user and radio_port. Provision the dedicated SSH key, verified known_hosts and bridge.yaml in the app configuration directory using the installation guide. The app uses the Supervisor’s MQTT service automatically.

        Open Gateway and check both Radio connection and MQTT. If the Pi is offline, the UI stays available and reconnects automatically. Check Pi power, its address, SSH access from Home Assistant, and that only one gateway owns the SX1302.

        2. Choose how to add sensors

        New or factory-reset sensor: put it in pairing mode following its model’s instructions, then open Devices. Select the discovered sensor and press Pair. Only reset a sensor if you intend to erase its previous pairing. For manual pairing, use adopt: [] in bridge.yaml; an explicit MAC allowlist pairs those sensors automatically.

        Existing UniFi sensor: open Import and review a JSON bundle containing its current persistent key and fallbackKey. Review never changes devices. Stop the previous controller, confirm that it no longer manages these sensors, and import. The sensor then reconnects using its existing keys. Temporary session keys cannot be imported.

        The optional SSH extractor connects to the original UniFi gateway, not the Pi radio host. Verify its fingerprint through a trusted connection before providing credentials. It temporarily restarts the source radio service; follow any recovery instructions before trying again.

        3. Verify the complete path

        1. Wait for fresh readings in Devices. Imported means saved; Connected means the sensor completed a radio handshake.
        2. In Home Assistant, open Settings → Devices & services → MQTT. Confirm that the SuperLink device and entities appear.
        3. Operate the sensor (for example, move the door magnet) and verify a new reading here and a matching entity change in Home Assistant.
        4. Use Refresh info and inspect Activity for a sensor response. Queued alone does not prove delivery. Sleeping devices may take time to respond.
        5. Back up the app configuration and device store. After a planned restart, verify reconnect and a fresh event again.

        Troubleshooting

        502 or bridge unavailable: check the app logs and retry. Access denied: reopen the Home Assistant sidebar panel to refresh Ingress, or check the standalone token. Home Assistant access tokens are not required for this panel.

        No MQTT entities: check broker connectivity, the Home Assistant MQTT integration, and matching discovery prefixes. Awaiting reconnect: wake the sensor, check radio coverage and gateway identity, and ensure the old controller has stopped. Do not repeatedly import or reset it.

        Radio outage: device commands are unavailable. Pending commands are discarded on reconnection because a timed-out transmission might already have executed. Inspect device state before submitting another command.

        Activity contains the latest 100 entries since app startup. Diagnostics exclude keys and credentials, but include device identifiers and readings.
